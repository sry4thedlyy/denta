# Дента — приложение стоматологической клиники

Закрытая тестовая версия с расписанием, карточками пациентов, каталогом услуг, историей приёмов и планами лечения. Интерфейс на русском языке; расписание использует московское время, цены — рубли.

## Что работает

- Расписание на выбранный день по врачам, список записей, поиск и фильтры.
- Создание, перенос, подтверждение, отметка прихода и отмена записи.
- Проверка пересечений по врачу и пациенту, включая параллельные запросы.
- Завершение приёма с обязательным результатом лечения; учёт оплаты.
- История услуги сохраняет название и цену на момент записи. Изменение каталога не переписывает старые записи.
- Карточка пациента: ФИО, телефон, дата рождения, адрес, паспорт, заметки, история приёмов, редактируемые этапы лечения.
- Добавление услуг, описаний, цен, длительности, категорий и архивация услуги.
- Добавление врачей, назначение и отключение ролей, журнал изменений и просмотра паспорта.
- Адаптивная компоновка для настольного и узкого экрана.

## Два варианта запуска

**Sites** — закрытая демонстрация. Только вымышленные данные. Использует инфраструктуру Cloudflare и вход ChatGPT; не предназначена для реальных данных российских пациентов.

**Собственный сервер в РФ** — автономный вариант в selfhost/. Клиент, API, SQLite, вход по паролю и шрифты размещаются на выбранном сервере. Работа приложения не требует обращения к Sites, ChatGPT, Google Fonts или другим внешним API. Caddy/ACME обращается за HTTPS-сертификатами, эти запросы не содержат досье пациентов.

Сам код не определяет географию: сервер, диски, резервные копии, журналы и хранилище ключей необходимо разместить в РФ. Российский сервер не был предоставлен, поэтому развёртывание там не выполнено.

## Запуск в РФ с Docker

Понадобятся российский сервер, Docker Compose и домен с DNS-записью на этот сервер. Не используйте международный CDN/прокси для трафика с досье без отдельного решения о размещении данных.

Из корня проекта:

1. Создайте секреты: node selfhost/init-secrets.mjs (Node.js 24+).
2. Скопируйте selfhost/env.example в selfhost/.env, задайте CLINIC_DOMAIN и ADMIN_EMAIL.
3. Выполните команду ниже.
4. Откройте свой HTTPS-домен. Начальный пароль администратора хранится в selfhost/secrets/admin_password. Скрипты не выводят секреты в журналы.
5. Создайте врачей и каталог услуг. Автономная база по умолчанию пустая.

    docker compose --env-file selfhost/.env -f selfhost/compose.yml up --build -d

Секреты создаются без перезаписи существующих файлов. Не генерируйте заново ключ при обновлениях: без прежнего ключа база и копии не расшифруются.

Compose запускает один API и Caddy. Порт API не публикуется; доступ идёт через HTTPS-прокси. API работает без root, с файловой системой только для чтения, кроме отдельного тома базы.

Docker в среде разработки отсутствовал: сборка, сервер и API проверены напрямую на Node.js; запуск контейнеров не проверен.

## Запуск на своём компьютере

Готовая сборка запускается на Node.js 24+ командой `npm run start:local`.
Приложение открывается по адресу http://127.0.0.1:3000/. Логин тестового администратора — `admin@denta.test`.
Путь к файлу начального пароля выводится в терминале при запуске.

Чтобы хранить локальную базу и ключ отдельно от исходников, укажите абсолютный путь к каталогу данных в `DENTA_LOCAL_STATE_DIR` через окружение или файл `.env.local` в корне проекта. В этой копии настройка указывает на существующую локальную базу вне OneDrive.

Для изменения исходников установите зависимости командой `npm ci` и обновляйте сборку командой `npm run build:selfhost`.

## Запуск без Docker

В архив включены исходники и готовая сборка selfhost-build/. Для готовой сборки нужен только Node.js 24+.

Переменные среды:

- APP_ORIGIN — точный адрес, например https://clinic.example.ru, без завершающего слэша.
- CLINIC_DATA_KEY_FILE — абсолютный путь к файлу ключа.
- ADMIN_PASSWORD_FILE — путь к начальному паролю, используется только при первом запуске.
- ADMIN_EMAIL — email первого администратора.
- DATA_DIR — каталог базы на защищённом диске в РФ.
- HOST — 127.0.0.1 за локальным HTTPS-прокси либо адрес внутри изолированной контейнерной сети.
- PORT — по умолчанию 3000.

Запуск:

    node selfhost/server.mjs

Только для локальной проверки допустимы APP_ORIGIN=http://127.0.0.1:3000 и ALLOW_HTTP_LOCAL=true. HTTP с любым другим именем хоста отвергается. DEMO_MODE=true заполняет новую базу вымышленными данными; существующую базу флаг не меняет.

Пересборка из исходников:

    npm ci
    npm run build:selfhost
    npm test
    node node_modules/typescript/bin/tsc --noEmit

## Сотрудники

1. Администратор добавляет email в «Врачи и сотрудники → Сотрудники», назначает роль и связывает с карточкой врача.
2. Системный администратор задаёт пароль через стандартный ввод:

    node selfhost/admin.mjs set-password doctor@example.ru < /protected/new-password

При Docker:

    docker compose --env-file selfhost/.env -f selfhost/compose.yml exec -T app node selfhost/admin.mjs set-password doctor@example.ru < /protected/new-password

Пароль передаётся сотруднику по отдельному защищённому каналу. Приложение не отправляет письма. Пароль — 14–256 символов. Повторная установка отзывает сессии сотрудника. Отключение роли запрещает дальнейшие обращения к API. Права владельца нельзя понизить через интерфейс.

## Реализованная защита

- Проверка личности и роли на сервере при каждой операции.
- Врач видит свои приёмы и закреплённых пациентов; паспорт и адрес ему не выдаются.
- Паспорт исключён из обычного ответа API. Просмотр администратором фиксируется и скрывается через 30 секунд или при уходе со вкладки.
- Клиническое хранилище зашифровано AES-256-GCM со случайным IV и проверкой целостности. Ключ отделён от исходников и базы.
- Автономные пароли защищены scrypt (N=131072, r=8, p=1) с уникальной солью; в базе хранится хеш случайного токена сессии.
- Cookie HttpOnly/SameSite=Strict; при HTTPS — Secure и префикс __Host-.
- Автономная сессия истекает через 15 минут без запросов или максимум через 8 часов. Интерфейс выходит через 15 минут без действий.
- Ограничение попыток входа и одновременных проверок пароля.
- Проверка Origin, размера запроса, параметризованные SQL-запросы.
- CSP автономного сервера запрещает внешние скрипты, подключения и встраивание.
- Досье не сохраняется в localStorage; ответы API не кешируются.

Настройки основаны на [OWASP Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html) и [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

## Резервная копия

    node selfhost/admin.mjs backup /protected/backups/clinic-YYYY-MM-DD.sqlite

Используется SQLite Online Backup API: копия согласована с WAL и содержит зашифрованные клинические данные. Каталог должен быть закрыт для остальных пользователей и находиться в РФ. Ключ резервируйте отдельно.

Для восстановления остановите API, сохраните текущие файлы, замените clinic.sqlite проверенной копией, уберите старые WAL/SHM только при остановленном процессе и используйте исходный ключ. Отзовите восстановленные сессии и проверьте записи. Создание/открытие копии проверено; полный аварийный сценарий необходимо отработать на целевом сервере.

## Границы версии

Это MVP для проверки процессов, а не подтверждённая готовность к промышленной работе с медицинскими данными. До реальных сведений нужно проверить инфраструктуру в РФ, доступ, резервирование, ключи и выполнение применимых требований с ответственным за защиту данных.

- Один экземпляр API, зашифрованный снимок до 1,8 МБ; для роста нужна миграция на таблицы с шифрованием отдельных полей.
- Журнал находится в том же снимке; он не является независимым неизменяемым аудитом всех чтений.
- Нет MFA, самостоятельного восстановления пароля, автоматической ротации ключей и расписания резервных копий.
- Врач видит историю своих приёмов; общая история доступна администратору.
- Один приём — одна услуга. Из этапа можно создать связанную запись. Завершение такого приёма закрывает этап, отмена позволяет записать пациента повторно.
- Отметка оплаты — внутренний учёт, не касса, чек или эквайринг.
- Нет интеграции с ЕГИСЗ, ЭП, страховыми системами, рентгеновскими файлами или SMS.
- Карточки не удаляются через UI; отменённые приёмы и архивные услуги сохраняются.
- Интерфейс сохраняет маркировку тестовой версии до завершения подготовки к рабочему запуску.

## Проверено

16 автоматических проверок: пересечения, время, исторические цены, статусы, роли, запрет повышения собственных прав, анонимный доступ и подделка заголовков, Origin, паспорт, аудит, устаревшая версия записи, шифрование, перезапуск, резервная копия и истечение сессии, редактирование этапов и связь с расписанием.

В браузере: настольная и узкая компоновки, конфликт/создание записи, карточка пациента и контролируемый просмотр демонстрационного паспорта.

Golos Text включён локально; лицензия SIL OFL — public/fonts/OFL.txt.
